# OctoVerse — сервер

Игровой сервер OctoVerse. **Спецификации здесь нет.** Замысел, числа, рецепты и
законы живут в вольте гейм-дизайна (`../octoverse-game-design`), откуда этот
репозиторий читает только `build/*.json`.

Разделение простое и его стоит держать:

| | Вольт | Этот репозиторий |
|---|---|---|
| Отвечает на вопрос | что должно быть верно и почему | как именно это сделано |
| Источник истины для | замысла, чисел, рецептов, законов | схемы хранения, API, тестов |
| Markdown читает движок | **никогда** | — |

Если движку понадобилось число, которого нет в `build/constants.json`, — это не
повод его зашить, а повод завести константу в вольте (D-065).

## Быстрый старт

```bash
docker compose up -d
```

```bash
python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"
```

```bash
cp .env.example .env
```

```bash
.venv/Scripts/python -m alembic upgrade head
```

Воркер — он же часы мира:

```bash
.venv/Scripts/python -m octoverse.worker
```

API:

```bash
.venv/Scripts/python -m uvicorn octoverse.api.app:app --reload
```

Тесты:

```bash
.venv/Scripts/python -m pytest -q
```

Тестам нужна база `octoverse_test`; без неё проверки, которым она нужна,
пропускаются, а чистая логика проверяется всё равно.

```bash
docker compose exec postgres psql -U octoverse -c "CREATE DATABASE octoverse_test OWNER octoverse;"
```

## Стек

Выбран в вольте (D-139), здесь только зафиксирован: Python 3.12+, FastAPI,
PostgreSQL 16, SQLAlchemy 2 (async) + asyncpg + Alembic, Pydantic v2, Redis.
Клиент — React + TypeScript, отдельным репозиторием.

Разрабатывается на Python 3.13: под 3.14 ещё не все колёса зависимостей собраны.

## «Свод»: откуда взялась каждая формула

В вольте заданы числа, но не порядок шагов — формулы дело движка. Вывод целиком
живёт в шапке [`engine/mining.py`](src/octoverse/engine/mining.py); коротко:

| Величина | Вывод | Из чего |
|---|---|---|
| Длина удара | `mine.roof_per_swing / mine.roof_start` часа | «шестнадцать ударов — длина короткой сессии» плюс «единиц за **час** добычи» |
| Выход за удар | `mining.iron_per_hour × длина удара × richness / mining.rich_threshold` | порог богатства и есть обычная жила |
| Стартовый свод | от `mine.roof_start` у бедной до `mine.roof_timber_cap` у богатой | «богатая жила даёт меньше — за богатство платят риском» |
| Темп | один множитель `mine.pace_k` на выход, просадку и выносливость | «во столько раз больше и выхода, и просадки, и расхода» |

**Ни одного числа сверх вольта здесь не появилось.** Если формуле не хватает
величины — её заводят в `data/constants.yaml`, а не в код.

### Что скрыто и почему это проверяется тестом

Устойчивость свода не показывается игроку никогда. Наружу уходит структура
`Sight`, где такого поля нет вовсе, — а сквозной тест проверяет **весь** обмен
по WebSocket на отсутствие лишних полей. Скрытое число не «спрятано в
интерфейсе»: его физически нет в ответе.

Признак врёт на `mine.sign_noise` в обе стороны. Без шума полосы обратимы
в арифметику, и скрытого числа больше нет.

## Шесть мест, где реализация обязана быть устроена именно так

Из [01-tech-notes](../octoverse-game-design/90-production/01-tech-notes.md).
Ошибка в любом из них не ловится тестами игры, но ломает игру.

### 1. Тик мира идемпотентен

Не «крон дёргает функцию», а журнал заданий с гарантией. Задание и его эффекты
фиксируются **одной транзакцией**: упал процесс посреди тика — откатилось всё,
задание осталось ожидающим. `dedup_key` не даёт поставить дубль, `FOR UPDATE
SKIP LOCKED` разводит воркеров без координации.

Следствие, о котором легко забыть: **эффект задания обязан быть в базе**. Всё,
что уходит наружу, ставится отдельным заданием.

### 2. Деньги — двойная запись

Поля `balance` не существует. Есть неизменяемый журнал проводок, баланс —
сумма по счёту. Сходимость операции в ноль проверяет **сама база** отложенным
триггером: несходящуюся операцию нельзя провести даже в обход движка.

Прирост денежной массы возможен только через счёт `genesis` — и потому виден.

### 3. Код-законы — интерпретируемые данные

Умолчания устава и код-законов берутся из `build/laws.json` при основании
города (D-130). Значения лежат в `JSONB`, движок собирает применимые записи и
проверяет их одним проходом. Ветвлений по типу закона в коде нет и не будет:
иначе каждый новый закон потребует релиза, и вся идея «игроки пишут правила»
умрёт.

### 4. Константы в памяти, но не в коде

`build/constants.json` разбирается в типизированный снимок при старте.
Константы, которой нет, ломает старт, а не бой. Каждое событие помнит отпечаток
набора — иначе разбор старого эпизода после правки баланса ничего не доказывает.

Отдельный тест (`tests/test_no_magic_numbers.py`) запрещает числовые литералы
в модулях правил. Величины исполнения (`runtime.py`) и представления
(`units.py`) под запрет не попадают — их невозможно «сбалансировать».

### 5. Агрегаты считает движок, а не дашборд

Одна формула на четверых потребителей: игровая торговая сводка (D-124),
дашборд, проверка инвариантов И1–И13 и симуляция. Grafana читает посчитанное,
а не пересчитывает.

*Ещё не реализовано — приезжает вместе с торговой сводкой.*

### 6. API действий не существует

Публичным может быть только чтение: цены, справочники, кодекс. Присутственное
действие идёт через сессию клиента (`/session/ws`) с платой устройства. Это
ограничение архитектуры, а не настройка: стоит появиться удобному REST для
«сделать удар», и добыча превращается в скрипт.

Проверяется тестом: любой POST/PUT/PATCH/DELETE в приложении — падение сборки.

**Опознание аккаунта в сессии — заглушка разработки.** Настоящая
аутентификация приезжает с подпиской (Э7, D-027); притворяться, что она уже
есть, хуже, чем честно назвать заглушку заглушкой.

## Устройство

```
src/octoverse/
  constants/      числа и каталоги из вольта: загрузка, типы, реестр, горячая замена
  db/             подключение, соглашения об именах, правила уровня базы
  models/         схема хранения
  engine/         то, что меняет мир: события, деньги, задания, тик
  api/            read-only поверхность
  units.py        как храним (минорные единицы, шкалы) — не баланс
  runtime.py      как исполняем (повторы, паузы) — не баланс
```

**Правило слоя:** состояние меняется только функциями `engine/`. Причина в
журнале: событие и его последствия обязаны фиксироваться вместе.

### Три величины, которые легко перепутать

| | Где живёт | Кто правит |
|---|---|---|
| **Балансное число** — выход руды, износ, ставка налога | `data/constants.yaml` вольта | гейм-дизайнер по телеметрии |
| **Величина исполнения** — повторы задания, пауза воркера | `runtime.py` | тот, кто держит сервер |
| **Величина представления** — минорные единицы денег, шкала 0…100 | `units.py` | никто, это способ хранения |

## Работа с вольтом

Правки чисел и рецептов делаются **только в `data/`** вольта, после чего там же
запускается `python tools/build.py`. Правка сгенерированного markdown будет
затёрта следующей сборкой.

Расхождение кода с документом вольта — **вопрос, а не молчаливая правка**.
Документ либо прав, либо устарел; решает человек.
