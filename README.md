# everse.life — сервер

Сайт игры и приём заявок на бету — **[everse.life](https://everse.life)**;
страница живёт в `landing/`.

Игровой сервер everse.life. **Спецификации здесь нет.** Замысел, числа, рецепты и
законы живут в вольте гейм-дизайна (`../everselife-vault`), откуда этот
репозиторий читает только `build/*.json`.

Разделение простое и его стоит держать:

| | Вольт | Этот репозиторий |
|---|---|---|
| Отвечает на вопрос | что должно быть верно и почему | как именно это сделано |
| Источник истины для | замысла, чисел, рецептов, законов | схемы хранения, API, тестов |
| Markdown читает движок | **никогда** | — |

Если движку понадобилось число, которого нет в `build/constants.json`, — это не
повод его зашить, а повод завести константу в вольте (D-065).

## Быстрый старт

Сервер живёт в `backend/`, и все команды ниже запускаются оттуда. Вольт
гейм-дизайна лежит рядом с этим репозиторием: `../everselife-vault`.

```bash
docker compose up -d
```

```bash
cd backend && python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"
```

```bash
cp .env.example .env
```

```bash
.venv/Scripts/python -m alembic upgrade head
```

Воркер — он же часы мира:

```bash
.venv/Scripts/python -m src.worker
```

API:

```bash
.venv/Scripts/python -m uvicorn src.api.app:app --reload
```

Стартовый мир и клиент — в [frontend/README](frontend/README.md):

```bash
.venv/Scripts/python -m src.seed
```

Тесты:

```bash
.venv/Scripts/python -m pytest -q
```

Тестам нужна база `everselife_test`; без неё проверки, которым она нужна,
пропускаются, а чистая логика проверяется всё равно.

```bash
docker compose exec postgres psql -U everselife -c "CREATE DATABASE everselife_test OWNER everselife;"
```

Прогон в несколько процессов — вдвое-втрое быстрее, каждому работнику
заводится своя база (`everselife_test_gw0`, `gw1`, …), заводится сама:

```bash
.venv/Scripts/python -m pytest -q -n 8
```

Больше восьми смысла обычно нет: работники делят один Postgres, а у него по
умолчанию сотня соединений.

Один раз на копию репозитория — включить хуки. Их три, и каждый закрывает свой
момент: `pre-commit` гоняет перед коммитом то же, что и CI, и предупреждает,
если чья-то ветка метит в того же родителя миграции; `pre-merge-commit`
отказывает, если мерж оставил бы две головы; `pre-push` — то же на выходе с
машины, потому что `--ff-only` и `git update-ref` коммита не создают и первых
двух не будят.

```bash
git config core.hooksPath .githooks
```

## Выкладка

Боевой состав — `deploy/compose.yaml`, порядок и сертификат — в
[DEPLOY.md](DEPLOY.md). Коротко: толчок в `main` → CI гоняет тесты, собирает два
образа и поднимает их на сервере; Caddy на границе сам берёт сертификат
Let's Encrypt.

Числа игры едут на сервер **внутри образа**, но в репозитории их нет: `vault/`
собирается в прогоне из вольта (`EverseLife/EverseLifeVault`), локально — тем же
`deploy/sync-vault.py`, и лежит в `.gitignore`. Отпечаток
загруженных констант виден в `/api/health` — по нему всегда понятно, на чём
работает боевой мир.

## Стек

Выбран в вольте (D-139), здесь только зафиксирован: Python 3.12+, FastAPI,
PostgreSQL 16, SQLAlchemy 2 (async) + asyncpg + Alembic, Pydantic v2, Redis.
Клиент — React + TypeScript, отдельным репозиторием.

Разрабатывается на Python 3.13: под 3.14 ещё не все колёса зависимостей собраны.

## «Свод»: откуда взялась каждая формула

В вольте заданы числа, но не порядок шагов — формулы дело движка. Вывод целиком
живёт в шапке [`engine/mining.py`](backend/src/engine/mining.py); коротко:

| Величина | Вывод | Из чего |
|---|---|---|
| Длина удара | `mine.roof_per_swing / mine.roof_start` часа | «шестнадцать ударов — длина короткой сессии» плюс «единиц за **час** добычи» |
| Выход за удар | `mining.iron_per_hour × длина удара × richness / mining.rich_threshold` | порог богатства и есть обычная жила |
| Стартовый свод | от `mine.roof_start` у бедной до `mine.roof_timber_cap` у богатой | «богатая жила даёт меньше — за богатство платят риском» |
| Темп | один множитель `mine.pace_k` на выход, просадку и выносливость | «во столько раз больше и выхода, и просадки, и расхода» |

**Ни одного числа сверх вольта здесь не появилось.** Если формуле не хватает
величины — её заводят в `data/constants.yaml`, а не в код.

### Что скрыто и почему это проверяется тестом

Устойчивость свода не показывается игроку никогда. Наружу уходит структура
`Sight`, где такого поля нет вовсе, — а сквозной тест проверяет **весь** обмен
по WebSocket на отсутствие лишних полей. Скрытое число не «спрятано в
интерфейсе»: его физически нет в ответе.

Признак врёт на `mine.sign_noise` в обе стороны. Без шума полосы обратимы
в арифметику, и скрытого числа больше нет.

## Крафт: откуда взялась каждая формула

Тот же принцип, что и в добыче: числа из вольта, порядок шагов из движка. Вывод
целиком — в шапке [`engine/craft.py`](backend/src/engine/craft.py); коротко:

| Величина | Вывод | Из чего |
|---|---|---|
| Время партии | `labor_hours(изделие) − Σ amounts × labor_hours(вход)` на единицу | вольт уже свёл сюда `craft.time_per_unit` и рост от глубины передела (D-133) |
| Скорость рабочей станции | `k = max − (max − min) × качество / шкала` | «множитель времени от качества рабочей станции: разбитая наковальня работает медленно» |
| Потолок качества | наименьшее из качества рабочей станции и инструмента | «ограничивает самое слабое звено» (15-quality) |
| Приближение к потолку | у сборки одни входы, у смеси `quality.material_weight` и `quality.ratio_weight` | D-092 |
| Оптимум пропорции | `amounts × (1 + (середина шкалы − качество основы) / шкала)` | «бедной руде нужно больше угля и флюса, чистой — меньше» |
| Потери и разброс | линейно по точности, от `*_share` до `*_bad_ratio` | порога «попал / не попал» в вольте нет, и выдумывать его нельзя |
| Премия ремесла | `quality.hand_craft_bonus × точность`, только у смеси | «до +10 за точное попадание в пропорции» |

**Количества входов берутся из `recipes.json`, а не из головы** (D-133) —
это отдельная проверка в тестах. Прогноз качества и партия считаются **одним и
тем же кодом**: прогноз, посчитанный отдельной функцией, рано или поздно
разойдётся с результатом, и обещание «игрок видит точное число до партии»
перестанет быть правдой.

Потери — доля **входов**, поэтому берутся сверх нормы: партия из десяти гвоздей
не даёт девять с половиной гвоздей, она съедает одиннадцатый слиток.

Чего в крафте пока нет и почему: блюда по ролям ждут готовки (Э2, D-119),
автоматическая станция — энергии (Э2.5, D-035), ремонт, переработка и
изобретение — своих действий реестра.

### Где стоит рабочая станция до появления зданий

Рабочая станция — предмет `kind: station`, и она лежит в контейнере узла
(`ContainerKind.NODE`), а не в кармане мастера: требование «станция в месте» и
делает крафт градообразующим. Со зданиями (Э3) станции переедут в них — станция
задаёт, чем здание является (D-106).

Готовое достаётся мастеру, если к сроку он всё ещё у станции; если ушёл или
погиб — остаётся лежать у неё. Материя не исчезает вместе с тем, кто её
заказал, и не телепортируется за ним.

### За рабочей станцией работает один (D-150)

Пока идёт партия, станция занята: второму мастеру она не отдаётся, а `busy_until`
страхует от вечной занятости, если партия исчезнет мимо своего задания.

Следствие важнее правила. Городская мастерская перестаёт быть бесплатным цехом
на весь город: мест в ней ровно столько, сколько рабочих станций. Ремесленнику
становится нужна **своя** рабочая станция, а значит и свой узел, куда её поставить, —
и у собственного дома впервые появляется смысл. Кому станция не нужна, тот
покупает готовое: это и есть разделение труда, ради которого существует рынок.

Ставят и уносят станции сами игроки (`engine/station.py`): в свой узел — хозяин,
в городской — тот, кому город дал полномочие `laws`. В ничьём узле за городом
ставить может всякий: земля там никому не принадлежит (D-198).

## Город: власть, казна и счета

Устав и код-законы лежали данными с самого начала, но менять их было некому.
Теперь у города есть три вещи и ни одной больше (D-154, шапка
[`engine/city.py`](backend/src/engine/city.py)):

| | Что это | Кто проверяет |
|---|---|---|
| **Должность** | «личность занимает пост в городе» | название придумывает город |
| **Право** | строка: `treasury`, `offices`, `land`, `charter`, `dashboard`, `justice`, `laws` — и точечное `law:<id>` | движок, и только его |
| **Казна** | счёт `city_treasury` на узле-представителе | двойная запись, как и всё прочее |

**Право дробится до одного закона** (D-155): `law:import_duty` открывает
пошлину на ввоз и ничего больше, а `laws` покрывает их все. Список конкретных
законов в коде не написан — он ровно тот, что лежит в `data/laws.yaml`: заведут
новый код-закон, под него сразу появится право. «Министр экономики» — это набор
прав, которому город дал имя.

Ветвлений по названию должности в коде нет и не будет: иначе каждая новая
форма правления потребовала бы выката версии. Отдать можно только то, что есть
у самого, — с учётом покрытия: держащий `laws` вправе выдать `law:toll`,
держащий `law:toll` — нет.

**Власть присутственна.** Закон, устав, назначение, трата казны и раздача
участков делаются **в администрации** города (D-155). Власть, осуществимая
из-за океана, не нуждается ни в столице, ни в дорогах к ней; администрация
становится точкой отказа: снесли или отключили за неуплату — управлять негде.
Чтение панели при этом остаётся удалённым: присутствие нужно, чтобы решать, а
не чтобы смотреть.

**Значение закона берётся в три шага:** решение города → умолчание `laws.json`
→ константа вольта, если умолчание записано ссылкой вида
`` `energy.tariff_default` ``. Город, не решивший ничего, живёт на умолчаниях
и работает с первой секунды (D-130).

### Счётчик: кто платит за быт (D-149)

    энергия = площадь × energy.home_draw_per_m2 × часы
    деньги  = энергия / 100 × тариф города

| Узел | Кто платит |
|---|---|
| занят игроком | владелец |
| принадлежит городу | **казна**: энергия уходит из пула и не продаётся |
| ничей | никто: счёт выставлять некому, а деньгам исчезать некуда (И2) |

Городская постройка приносит городу налоги; брать за неё с посетителя значило
бы брать плату дважды. Власть, ставящая мастерскую, обязана понимать, что
содержит её казна, — в этом и состоит решение.

**Не заплатил — отключён**: долг остаётся на узле, рабочие станции в нём стоят. Отобрать
узел за долг движок не вправе: это решение суда, а не арифметики.

### Экономическая панель города (D-124, D-140)

Рычаг без прибора бесполезен: власть получила ставки и запреты, но узнать, что
происходит, могла только по жалобам в чате. Панель считается движком шагом
`trade.report_window` и показывает шесть разделов — товары, рынок, казна,
энергия, люди, производство ([`engine/panel.py`](backend/src/engine/panel.py)).

| Правило | Почему так |
|---|---|
| Шаг медленнее рынка | мгновенные данные дали бы власти торговое преимущество перед собственными купцами |
| Публичный срез виден всем | если цифры видит только правитель, спорить с ним нечем и выборы становятся вкусовщиной (D-047) |
| Казна по статьям — по праву `dashboard` | одной суммой панель бесполезна: решать нужно по основаниям |
| Персонального нет ни у кого | иначе городская панель превращается в слежку, а приватность в декорацию (D-081) |
| Без администрации город слеп | панель живёт, пока стоит и содержится ратуша: у постройки появляется смысл помимо расхода |

История ложится в ту же таблицу суточных метрик, что и срез мира: формула одна
на игровую панель, дашборд разработчика и проверку инвариантов (D-139).

### Подъёмные новичку (D-153)

Игрок печатается с **нулём на счету**: мир денег не выдаёт, потому что любой
такой выпуск размывает деньги всех остальных. Город вправе платить подъёмные из
своей казны — код-закон `newcomer_grant`, значение задаёт власть. Это перевод, а
не эмиссия.

Почему город на это идёт: новый житель — это ВВП, он покупает, продаёт и платит
налоги. Богатый город переманивает новичков, бедный не может себе этого
позволить, — и это первая настоящая конкуренция между городами.

## Смерть: что теряется и две двери обратно

Личность бессмертна, тело — расходник (D-012). Гибель уничтожает оболочку и всё,
что она несла; знания, счёт, участки, ордера и товар в терминале переживают её,
потому что принадлежат личности, а не телу. Вывод — в шапке
[`engine/death.py`](backend/src/engine/death.py).

| Правило | Как сделано |
|---|---|
| Уцелевает часть | `death.salvage_ratio` носимого остаётся **на месте гибели** и в повреждённом виде: состояние падает в той же доле |
| Обвал хоронит | смерть в забое оставляет **весь** карман лежать в узле и целым: порода накрывает тело и груз в одном месте, и доля сюда не применяется (D-294) |
| Печать в городе | `energy.body_print` энергии из пула по тарифу плюс `death.iron_cost` железа со двора; готово через `death.print_time_city` минут |
| Печать у Предтеч | бесплатно и без ограничения по числу тел, но `death.print_time_capital` часов |
| Кто платит | код-закон `body_print` (D-032): `nobody` — сам игрок, `citizens` — казна за своих, `everyone` — за всех |
| Первое тело | мгновенно и бесплатно (D-040): человек, впервые запустивший игру, не ждёт полсуток |

**Город продаёт не жизнь, а скорость.** Отсюда потолок цены воскрешения: никто
не заплатит за тело больше, чем стоят ему двенадцать часов. И отсюда же
невозможность заложника: печататься можно в любом узле Сети, где есть принтер и
чем заплатить (D-033), а бесплатная дверь столицы не закрывается никогда.

**Гибель в альфе одна — среда** (D-111): обвал свода, и он не бросает кости —
тело переживает `mine.collapses_survived` обвалов, следующий убивает (D-294).
Боя нет, и до его возвращения других способов умереть в мире не существует.

## Таможня: ставка и норма вместо шлагбаума (D-123)

Задача власти звучит не «закрыть границу», а «наши фермеры не выдерживают
дешёвого привозного хлеба» и «наши цеха стоят без руды, потому что её всю
вывезли». Шлагбаумом это не решается, поэтому законов четыре:

| Закон | Что задаёт |
|---|---|
| `import_duty` · `export_duty` | товар, ставку % и беспошлинную норму кг за `trade.duty_free_window` |
| `import_ban` · `export_ban` | список того, что не проходит вовсе |

**Норма делает пошлину прицельной.** Ставка без порога бьёт по всем одинаково,
и первым страдает новичок, привёзший мешок репы себе на ужин. Норма считается
**на человека и за окно**, а не за одну ходку: иначе её обходят, разбив груз на
десять заходов.

**Стоимость — справочная цена городского стакана**, медиана сделок за
`trade.reference_price_window`. Нет сделок — нет оценки, и пошлина не берётся:
сначала рынок, потом таможня.

**Считается на выходе в дорогу**, когда обе стороны границы уже известны:
платить на приходе значило бы пускать в город то, за что заплатить нечем. Не
хватило денег — переход не начинается, и **долга не возникает**: решение, что
бросить, принимает человек, а не таможня за него.

Контрабанда через подставных перевозчиков остаётся возможной, и это не дыра:
каждый мул — живой человек, тратящий своё время на переход. Таможня без обхода
перестаёт быть политикой и становится физикой (D-123).

## Разведка: откуда берётся мир за стенами (D-152)

Карта прирастает игроками, а не патчем. Заход идёт заданием журнала и кончается
броском. **Пустой заход — норма:** без него карта росла бы кликом.

**Цена захода — свойство места, а не игрока** (D-156). У каждого узла есть счёт
находок, сделанных, когда из него выходили:

| Находок отсюда | Заход | Шанс |
|---|---|---|
| 0 | `explore.attempt_minutes` — минуты | `explore.find_chance` |
| каждая следующая | ×`explore.effort_growth`, до потолка `explore.attempt_hours` | ×`explore.find_decay`, до пола `explore.find_floor` |

Счёт живёт на узле, а не на игроке: уровень разведки был бы прокачкой, а
исхоженная окрестность беднеет для всех сразу. Заход от свежей находки снова
дёшев — поэтому карта растёт вширь, а не звездой из точки рождения.
Выносливость берётся по времени в поле: `explore.attempt_stamina` — цена захода
полной длины. Прогноз (`explore.outlook`) клиент показывает **до** выхода: цена,
меняющаяся от места к месту, не может быть невидимой.

**Цель выбирает игрок**, и от неё зависит, что окажется на карте:

| Цель | Где ищут | Что находят |
|---|---|---|
| `lot` | на слое города | свободный участок — он встанет **городской** землёй (D-089) |
| `site` | на планете | место под будущий город |
| `vein` | на планете | жилу; породу можно назвать заранее |

**Названная порода ищется хуже безымянной** — ровно во столько раз, во сколько
она реже по `harvest.rates`. Иначе все искали бы только самое дорогое, и
разведка стала бы краном. Порода без заказа выбирается из `gives` операции
«Добыча» тем же весом; списка «какие бывают руды» в движке нет — заведут в
вольте пятую, она начнёт находиться сама.

Найденное за стенами **ничьё**: нашедший получает право первой ночи, а не
собственность. Городскую землю не занимают — её раздаёт власть (`city.allot`).

## Стакан: что где происходит

Книга заявок местная и только местная (D-003): единая цена схлопнула бы
географию вместе с перевозчиком. Движок товар **не оценивает** — он сводит
встречные заявки, и цена есть то, что кто-то согласился заплатить (D-002).
Подробности — в шапке [`engine/market.py`](backend/src/engine/market.py).

| Действие | Где | Почему |
|---|---|---|
| Загрузить товар в терминал | присутственно | материя перемещается только физически |
| Выставить и снять ордер на продажу | удалённо | товар привезён, дальше он биржевой актив |
| Купить | присутственно | иначе стаканы всех городов скупаются не вставая |
| Забрать купленное | присутственно | то же правило материи |
| Смотреть стаканы любых узлов | удалённо, публично | цены знают все (D-047) |

**Покупка — это выставление лимитной заявки**, поэтому присутствие требуется
именно на ней. Остаток висит в стакане, деньги под него заморожены, купленное
ложится в терминал и ждёт ног. Товар торгуется **позициями вида «руда,
хорошая»**: ступени из `quality.tiers`, потому что непрерывная шкала сделала бы
книгу нечитаемой и убила ликвидность (D-058).

| Величина | Правило |
|---|---|
| Приоритет | лучшая цена, при равной — кто раньше встал |
| Цена сделки | цена **стоявшего** в стакане: он назвал условие первым |
| Заморозка | `цена × объём` при постановке; исполнилось дешевле — разница возвращается сразу |
| Налог | `tax_trade` платит продавец с выручки (D-127); покупатель платит ровно то, что видит |
| Комиссия | `market.default_fee`, пока владелец терминала не задал свою |
| Срок | `market.order_lifetime` терранских суток, снимается заданием журнала |

**Узел ничей — удержаний нет вовсе.** Не потому что так задумано, а потому что
платить их некому: деньги не могут исчезать в никуда. Ставки поедут из
код-законов, когда появятся города (Э3).

## Карта: граф, а не сетка

Мир — **взвешенный граф**, и это выбор с последствиями: у графа есть узкие
места — мост, перевал, единственный вход в долину, — а значит есть за что
драться, где ставить пошлину и где устраивать засаду. На сетке ничего этого
нет. Вывод формул — в шапке [`engine/travel.py`](backend/src/engine/travel.py).

| Правило | Как сделано |
|---|---|
| Ребро ненаправленное | одна строка на пару узлов: дорога одинакова в обе стороны |
| Время перехода | `base_seconds × road.<покрытие>_multiplier`: бездорожье вдвое-втрое дольше, тракт быстрее |
| Приход | задание журнала на срок, а не проверка при чтении: закрыл вкладку — всё равно придёшь |
| Пока идёшь — тебя нет | добыча, крафт, погрузка, покупка и Библиотека закрыты; ордера и счёт работают |
| По прямой не ходят | нет ребра — нет пути, и телепорта в этом мире не будет |
| Дорога стоит тела | `travel.stamina_per_hour` за час пути, с транспортом — ноль (D-147) |

**Присутствие проверяется в движке, а не в клиенте.** Одна функция
`travel.require_here` стоит на всех присутственных действиях: спрятать кнопку
мало, потому что кнопка — не защита.

Шаг внутри города — секунды (`travel.city_step`), выход за стену — десятки
минут (`travel.frontier_step`). Эта разница и есть вся география: до рабочей
станции сходить дёшево, за углём — выезд.

**Вторая цена дороги — выносливость** (D-147). Время плохо годится в цену:
закрыл вкладку и пришёл. Расход считается от времени, а не от числа переходов,
— иначе шаг по кварталу стоил бы столько же, сколько переход через степь.
С обозом расход множится на `transport.stamina_k` = 0: везёт транспорт, а не
ноги. Списывается вперёд: выйти в дорогу, на которую не хватает сил, нельзя, а
автопуть обрывается там, докуда хватило.

### Обоз: три состояния и одна дорога (D-157)

Предел носимого (`inventory.carry_mass`) — это причина существования повозок, и
до D-157 он был тупиком: повозка тяжелее предела и в руки не бралась вовсе.
Теперь у транспорта три состояния — **стоит** в узле, **впряжён** в тело,
**гружён**; вывод целиком в шапке
[`engine/transport.py`](backend/src/engine/transport.py).

| Правило | Как сделано |
|---|---|
| Груз едет в трюме | контейнер вида `vehicle` на `transport.capacity` кг; из рук в трюм — присутственно |
| Обоз идёт быстрее | `transport.speed_k`: тачка медленнее ног, повозка быстрее |
| Бездорожье не пускает | `Surface.TRAIL` закрыт для транспорта совсем, `ROAD` — только для лёгкого до `transport.heavy_from`, `PAVED` — для любого |
| Маршрут строится по проходимым | Дейкстра с обозом ходит по тем же рёбрам, но урезанному графу; упёрся — остановился на последнем узле |
| Износ за отрезок | `wear.transport_per_leg` × (1 + загрузка): полный трюм изнашивает вдвое сильнее пустого |
| Поломка — остановка, а не потеря | разбитая повозка кончается (столп П2), груз остаётся лежать в узле, упряжка распадается, маршрут обрывается |

**Почему трюм, а не прибавка к рукам.** Прибавкой было бы проще —
`inventory.carry_bonus` у рюкзака так и работает. Но тогда груз распрягшегося
возчика телепортировался бы ему в руки или испарялся, а сорок мешков зерна
обязаны остаться в повозке там, где она встала.

Отсюда главное следствие: **дорога — предусловие торговли, а не удобство.** До
узла, найденного разведкой, телега не доедет, пока к нему не проложат дорогу, —
а укладка дорог (`road.surface_per_edge`) ещё впереди.

### Корабль — подграф, который отстыковывается (D-201, D-202)

Космический корабль — **не предмет и не транспорт, а группа узлов того же
графа**: рубка, трюм, каюты, машинное. Узел борта — обычный узел со своей
площадью, своим чатом и своими рабочими станциями. Наружу группа выходит **ровно
одним узлом-коннектором**, и он смыкается с космодромом обычным ребром.

Отсюда весь космос сводится к двум операциям над одним ребром:

| Что в игре | Что в движке |
|---|---|
| Швартовка | `travel.connect` коннектора с узлом космодрома или орбиты |
| Отход и полёт | `travel.disconnect` — ребра нет, корабль недостижим |
| Подъём, переход, спуск | то же самое с орбитой или другим космодромом на конце (D-245) |
| Зайти на борт, ходить по кораблю | обычный переход и обычный автопуть |
| Досмотр и захват | происходят на коннекторе: узкое место ровно одно |

**Ни одного нового понятия в карте не появилось.** Узлы борта — обычные узлы,
принадлежность кораблю — та же иерархия `parent`, что у города над локациями
(D-097), а до D-201 граф только рос: разведка добавляла узлы (D-152), дорога
меняла покрытие (D-158), но ни одно ребро не исчезало. Теперь ребро
**снимается** — по-настоящему, а не помечается закрытым: второе состояние
пришлось бы учитывать в маршруте, в разведке, в сцене узла и в досмотре, а
отстыкованный корабль обязан быть недостижим ровно по той причине, по которой
недостижим любой несвязный кусок карты.

Три следствия, ради которых это сделано именно так:

- **Ребро под идущим не снимается** (`travel.EdgeInUse`): иначе переход повисает
  между узлом, которого больше нет рядом, и телом, которому некуда прийти.
  Отстыковка ждёт, пока трап освободится;
- **маршрут — план, а не обещание**: автопуть, проложенный через исчезнувшее
  ребро, обрывается там, докуда дошли, — тем же способом, что при нехватке сил
  и на таможне, а не падением задания;
- **`travel.edge_id` теперь может быть пустым**: журнал уже пройденных отрезков
  переживает исчезновение дороги, по которой шли. Отрезок в пути его не теряет
  никогда — снять такое ребро нельзя.

### Как корабль строится и летит (D-202)

Рецепта «корабль» нет. Игрок приходит на космодром, отдаёт «Основу узла
корабля» — и через `ship.foundation_hours` появляется первый узел: он же
основание, он же коннектор, он же точка стыковки. То же действие с борта
добавляет ещё один узел, связанный с тем, откуда закладывали.

| Правило | Как сделано |
|---|---|
| Узел борта — **здание с первой секунды** | иначе двигателю негде стоять: рабочая станция ставится в здание и занимает площадь (D-106). Площадь — `ship.node_area` |
| Что корабль умеет, задаёт то, что в нём стоит | двигатель, навигация и жизнеобеспечение — `kind: station`, ставятся обычным `station.place` |
| Узел борта принадлежит владельцу корабля | ничей узел открыт всем (D-198), и чужой унёс бы двигатель. Титула при этом нет: борт — имущество, а не земля |
| Тяга и класс — из вольта **по названию** | `ship.thrust` и `ship.engine_class`, как грузоподъёмность у транспорта: списка двигателей в коде нет (D-090) |
| Скорость | `время = табличное × ship.reference_ratio / тяговооружённость`, с полом `ship.route_min_share` |
| Перегруз | ниже `ship.min_thrust_ratio` корабль не идёт никуда, и сводка говорит об этом **до** попытки |
| Экипаж | числа нет (D-288): система жизнеобеспечения одна на корпус и дышит за всех из баллонов на своей линии; без системы рейс не начинается |
| Топливо | `ship.fuel_per_ton_day` × масса × сутки, списывается при выходе. Лишний узел стоит денег на каждом рейсе |
| Нога требует топлива **на выход из своего конца** | подъём — на подъём и спуск обратно, переход — на переход и посадку в конце. У корабля без рёбер нет способа получить помощь: топливо не привезут, с борта не сойти. Ловушек без выхода не делают (П6) |
| Разведка с борта закрыта | находка приходит с ребром от узла, откуда выходили, — это был бы второй вход мимо коннектора |
| Рейс | отход снимает ребро, задание журнала ждёт срок, приход ставит ребро на другом конце. Пассажир всё время стоит в своём узле — переезжает не он, а его сосед |
| Дорога — три ноги (D-245) | космодром → околопланетная орбита → орбита другой планеты → её космодром. Подъём и спуск считаются по `planet.gravity`, переход — по небу; с земли между планетами не ходят, с орбиты садятся только на планету под собой |
| Подъём можно отменить | `ship.recall` разворачивает любую ногу, и подъём садится обратно на тот же космодром. Не дешевле спуска: иначе взлёт-разворот пропускал бы часы посадки |
| Орбита — пустота | узел несёт планету ради маршрутов, но воздуха у него нет: выход туда — выход в открытый космос (D-233) |

Маршруты не хранятся: перелёт считается по орбитам (D-271), пара планет ключом
«пара планет по алфавиту»: маршрут ненаправленный, как ребро карты. Внутри
планеты перехода нет вовсе — есть подъём (`ship.ascent_hours`) и спуск
(`ship.descent_hours`), каждый со своим множителем тяжести.

**Чего ещё нет:** космических узлов и коридоров (перехватывать груз пока негде —
рейс идёт из порта в порт), узлов на других планетах (маршруты в данных есть,
мира на том конце нет), разбора корабля и его гибели — она приезжает вместе с
боем (D-111).

## Износ: два числа, которые путают чаще всего

На предмете два числа 0–100. **Качество** — каким сделан, не меняется никогда.
**Состояние** — насколько изношен сейчас. Вывод формул — в шапке
[`engine/wear.py`](backend/src/engine/wear.py):

| Величина | Правило |
|---|---|
| Скорость износа | базовый расход **делится** на `quality.durability_factor`: хорошая кирка служит дольше ровно во столько раз, во сколько она лучше |
| Действующее качество | качество × доля оставшегося состояния: разбитая наковальня даёт худший результат, а не только внезапно ломается |
| Конец вещи | состояние ноль — предмет исчезает; ориентир приёмки прямой: `100 / wear.tool_per_session` сессий |
| Среда | `wear.environment_k` множит износ снаряжения: Пироксис дорог сам по себе |
| Ремонт | стоит `craft.repair_cost_share` от новой вещи — и материалами, и временем; потолок состояния падает на `quality.repair_ceiling_loss` |
| Переработка | возвращает `craft.recycle_return` материалов качеством `quality.recycle_carryover` от исходного; разница — сток |

### Формула вольта вычисляется, а не переписывается кодом

`quality.durability_factor` задан в `build/constants.json` выражением
`base_life * (0.5 + quality / 80)`. Переписать его кодом — значит переселить
числа `0.5` и `80` в движок, после чего правка баланса потребует выката версии,
чего D-065 прямо запрещает. Поэтому выражение **считается**
([`constants/formula.py`](backend/src/constants/formula.py)): разрешены
арифметика, скобки и подстановка имён, и ничего больше. Формула, описывающая
алгоритм — `sum(... for n in 1..floors)` у сметы стройки, — честно отвергается
как невычислимая: это код, и движок обязан написать его сам.

## Шесть мест, где реализация обязана быть устроена именно так

Из [01-tech-notes](../everselife-vault/90-production/01-tech-notes.md).
Ошибка в любом из них не ловится тестами игры, но ломает игру.

### 1. Тик мира идемпотентен

Не «крон дёргает функцию», а журнал заданий с гарантией. Задание и его эффекты
фиксируются **одной транзакцией**: упал процесс посреди тика — откатилось всё,
задание осталось ожидающим. `dedup_key` не даёт поставить дубль, `FOR UPDATE
SKIP LOCKED` разводит воркеров без координации.

Следствие, о котором легко забыть: **эффект задания обязан быть в базе**. Всё,
что уходит наружу, ставится отдельным заданием.

### 2. Деньги — двойная запись

Поля `balance` не существует. Есть неизменяемый журнал проводок, баланс —
сумма по счёту. Сходимость операции в ноль проверяет **сама база** отложенным
триггером: несходящуюся операцию нельзя провести даже в обход движка.

Прирост денежной массы возможен только через счёт `genesis` — и потому виден.

### 3. Код-законы — интерпретируемые данные

Умолчания устава и код-законов берутся из `build/laws.json` при основании
города (D-130). Значения лежат в `JSONB`, движок собирает применимые записи и
проверяет их одним проходом. Ветвлений по типу закона в коде нет и не будет:
иначе каждый новый закон потребует релиза, и вся идея «игроки пишут правила»
умрёт.

### 4. Константы в памяти, но не в коде

`build/constants.json` разбирается в типизированный снимок при старте.
Константы, которой нет, ломает старт, а не бой. Каждое событие помнит отпечаток
набора — иначе разбор старого эпизода после правки баланса ничего не доказывает.

Отдельный тест (`tests/test_no_magic_numbers.py`) запрещает числовые литералы
в модулях правил. Величины исполнения (`runtime.py`) и представления
(`units.py`) под запрет не попадают — их невозможно «сбалансировать».

### 5. Агрегаты считает движок, а не дашборд

Одна формула на четверых потребителей: игровая торговая сводка (D-124),
дашборд, проверка инвариантов И1–И13 и симуляция. Grafana читает посчитанное,
а не пересчитывает.

*Ещё не реализовано — приезжает вместе с торговой сводкой.*

### 6. API действий не существует

Публичным может быть только чтение: цены, справочники, кодекс. Присутственное
действие идёт через сессию клиента (`/session/ws`) с платой устройства. Это
ограничение архитектуры, а не настройка: стоит появиться удобному REST для
«сделать удар», и добыча превращается в скрипт.

Проверяется тестом: любой POST/PUT/PATCH/DELETE в приложении — падение сборки.

**Опознание аккаунта — почта и пароль** (D-187): `hello` принимает почту с
паролем либо жетон прежнего входа; регистрация (`join`) заводит аккаунт,
личность и первое тело одной командой. Подписка (Э7, D-027) привяжется к тому же
аккаунту. Стартовым личностям сида почта и пароль назначаются сидом же — см.
`FOUNDERS` в `backend/src/seed_parts.py`.

## Устройство

```
backend/src/
  constants/      числа и каталоги из вольта: загрузка, типы, реестр, горячая замена
  db/             подключение, соглашения об именах, правила уровня базы
  models/         схема хранения
  engine/         то, что меняет мир: события, деньги, задания, тик, добыча, крафт
  api/            read-only поверхность плюс сессия клиента
  units.py        как храним (минорные единицы, шкалы) — не баланс
  runtime.py      как исполняем (повторы, паузы) — не баланс
```

Клиент живёт в [`frontend/`](frontend/README.md) — альфа-клиент с картой-графом,
сценами локаций и живым чатом; визуальный язык временный (D-051). Вольт
гейм-дизайна лежит рядом с репозиторием, в `../everselife-vault`.

**Правило слоя:** состояние меняется только функциями `engine/`. Причина в
журнале: событие и его последствия обязаны фиксироваться вместе.

### Три величины, которые легко перепутать

| | Где живёт | Кто правит |
|---|---|---|
| **Балансное число** — выход руды, износ, ставка налога | `data/constants.yaml` вольта | гейм-дизайнер по телеметрии |
| **Величина исполнения** — повторы задания, пауза воркера | `runtime.py` | тот, кто держит сервер |
| **Величина представления** — минорные единицы денег, шкала 0…100 | `units.py` | никто, это способ хранения |

## Работа с вольтом

Правки чисел и рецептов делаются **только в `data/`** вольта, после чего там же
запускается `python tools/build.py`. Правка сгенерированного markdown будет
затёрта следующей сборкой.

Расхождение кода с документом вольта — **вопрос, а не молчаливая правка**.
Документ либо прав, либо устарел; решает человек.

Лестницу рецептов удобнее смотреть и править графом, а не в YAML — для этого
есть редактор, и живёт он **в самом вольте** (`everselife-vault`, каталог
`editor/`): граф «что из чего», поиск, создание, правка и удаление рецептов,
кнопки проверки и сборки. Здесь его больше нет — он правит `data/recipes.yaml`,
а не код движка.

```bash
# из корня вольта
python editor/server.py
```
