# Мост с Discord: как включить и как проверить

Три ленты наружу, ни одной команды внутрь. Разговор о том, почему мост
односторонний, — в [`discord.md`](discord.md#что-делает-бот); здесь только
порядок действий.

| Лента | Кто пишет | Настройка |
|---|---|---|
| Хроника мира → `#хроника` | воркер игры, `backend/src/herald/` | `OCTOVERSE_DISCORD_WEBHOOK` в `/opt/octoverse/.env` |
| Заявки на бету → `#заявки` | лендинг, `landing/app.py` | `LANDING_DISCORD_WEBHOOK` там же |
| Выкладки → `#выкладки` | CI, `.github/workflows/ci.yml` | секрет `DISCORD_DEPLOY_WEBHOOK` на GitHub |

Ни в одном случае бот в Discord не нужен: три вебхука, каждый умеет писать
ровно в свой канал и ничего больше.

## 1. Завести вебхуки

В Discord: канал → **Настройки канала** → **Интеграции** → **Вебхуки** →
**Создать вебхук**. Имя — «Глашатай» (для хроники), «Заявки», «Выкладки».
Скопировать ссылку.

Ссылка вебхука — **пароль**: кто её знает, тот пишет в канал. В репозиторий её
класть нельзя; место для неё — `.env` на сервере и секреты GitHub.
Утёкшую — удалить кнопкой в том же окне и завести новую.

## 2. Включить на сервере

```bash
cd /opt/octoverse
nano .env       # OCTOVERSE_DISCORD_WEBHOOK и LANDING_DISCORD_WEBHOOK
docker compose up -d --force-recreate worker landing
```

Хронику относит **воркер**, а не сервер API: пересоздавать `backend` незачем.
Первый проход после включения ничего не пришлёт — лента начинается с текущего
события журнала и историю мира не досылает. Ждать до первой строки — сколько
уйдёт до первого достойного события, но не дольше двух минут после него.

## 3. Включить в CI

GitHub → Settings → Secrets and variables → Actions → **New repository
secret**: имя `DISCORD_DEPLOY_WEBHOOK`, значение — ссылка вебхука канала
`#выкладки`. Пока секрета нет, шаг молчит и прогон от этого не краснеет.

## 4. Проверить

**Вебхук отвечает** (с любой машины):

```bash
curl -sS -H 'Content-Type: application/json' \
  -d '{"content":"проверка связи","allowed_mentions":{"parse":[]}}' \
  "<ссылка вебхука>"
```

Пусто в ответе и сообщение в канале — работает. `401`/`404` — ссылка не та
или вебхук удалён.

**Глашатай жив** — на сервере:

```bash
docker compose logs worker | grep глашатай
```

`глашатай начинает ленту с события N` — завёлся. `глашатай отнёс N строк
хроники` — отнёс.

**Задание идёт** — в базе всегда стоит ровно одно будущее звено:

```bash
docker compose exec postgres psql -U octoverse -d octoverse \
  -c "select state, run_at, payload from job where kind='herald.post' order by run_at desc limit 3"
```

Состояние `failed` у последнего — цепочка оборвалась; она заведётся заново при
следующем перезапуске воркера, но причину видно в поле `last_error`.

**Локально, без сервера**: поднять воркер с переменной среды и дождаться
события — например, основать город. Молчание при пустой переменной — норма.

## Что попадает в хронику

Белый список — в `backend/src/herald/chronicle.py`, словарь `LINES`. Сейчас в
нём восемь видов событий: основание города, код-закон, устав, итог
голосования, место в совете, приговор суда, ключевая ставка, находка разведки.

**Добавить событие** — дописать в `LINES` строку и функцию к ней. Прежде чем
дописывать, ответьте на один вопрос: видит ли этот факт в игре посторонний?
Если нет — событию в ленте не место, сколько бы красиво оно ни звучало. Тест
`tests/test_herald.py::test_личное_наружу_не_уходит` держит границу со стороны
денег, вещей, тела и разговоров, но всех будущих ошибок он не поймает: список
там перечислительный, а решение — ваше.

Отдельно про разведку: в ленту уходит найденный узел (карта и так публична) и
**не уходит порода жилы**. Находка — плата разведчику за риск; объявить её
всему миру значит эту плату отобрать.

## Известные углы

* **Дубль после сбоя.** Отправка идёт внутри транзакции задания. Если Discord
  принял сообщение, а фиксация не прошла, повтор пришлёт те же строки второй
  раз. Дубль в ленте дешевле пропуска, поэтому так и оставлено.
* **Простой не досылается.** Оборвавшаяся насовсем цепочка заводится заново с
  чистого листа: пропущенное за время простоя остаётся в журнале событий и в
  канал не приезжает. Это лента, а не журнал.
* **Порядок строк — по журналу.** Внутри одного прохода строки идут по
  возрастанию `event.id`, то есть в порядке, в котором мир их и записал.
* **Имена игроков экранируются.** Разметка Discord в имени города обезврежена,
  упоминания отключены целиком (`allowed_mentions`). Город с именем
  `@everyone` никого не дёрнет.
