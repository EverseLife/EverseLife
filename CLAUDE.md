# everse.life — правила для Claude

## Язык кода: только ASCII

- **Все идентификаторы — только на английском языке**: имена переменных, функций,
  классов, параметров, полей, фикстур, тестов, констант, React-стейтов и т.д.
  Кириллица (и любые не-ASCII символы) в идентификаторах запрещена. Это касается
  Python, TypeScript/TSX, CSS-классов, SQL, YAML, конфигов.
- **Комментарии, докстринги и лог-сообщения — на английском.** Ссылки на решения
  вольта (`D-065`, `10-world/07`) сохраняются как есть.
- **Идентификаторы контента — устойчивые ключи D-251**: предметы, станции,
  рецепты, классы, тиры, слоты, свойства узлов в коде, базе, тестах и в проводе
  сокета пишутся snake_case-ключами (`iron_ore`, `coin_station`) из
  `vault/renames.json`. Русское имя — слой показа: клиент и APS берут его по
  ключу из `/public/renames` (`names_ru`), движок — из `current_renames()`.
  Новый русский литерал в роли идентификатора — регресс волны II.
- **Исключение — строки, обращённые к игроку или сообществу**: отказы движка
  (`raise CoinError("...")`), тексты интерфейса в JSX, сообщения деплоя в
  Discord, `landing/index.html`, а также имена и описания в данных вольта
  (поле `name` при английском `id`). Они остаются на русском — это язык игры,
  а не кода (до локалей волны III D-251).
- Перед завершением правки проверь, что новых не-ASCII идентификаторов и
  комментариев не появилось (например, `grep -nP '[^\x00-\x7f]'` по изменённым файлам).

## Параллельные сессии в одной копии

Здесь нередко работают две сессии Claude Code сразу, и три ресурса у них общие.

- **Тестовая база.** Фикстуры чистят таблицы перед каждым тестом, а схему
  собирают заново в начале прогона, поэтому два `pytest` сносят данные друг у
  друга: получается `DeadlockDetectedError` или `column ... does not exist` —
  падений много, они разнородные и выглядят как настоящая поломка. Прежде чем
  чинить непонятные падения, проверь, не идёт ли чужой прогон:
  `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` и отфильтруй по
  `*pytest*`. Чужой процесс не убивать.
- **Своя база вместо очереди.** `tests/conftest.py` читает
  `EVERSELIFE_TEST_DATABASE_URL`, так что достаточно завести отдельную базу и
  передавать её в той же команде (переменные окружения между вызовами не
  сохраняются):
  `$env:EVERSELIFE_TEST_DATABASE_URL='postgresql+asyncpg://everselife:everselife@localhost:5432/everselife_test_b'; .venv/Scripts/python.exe -m pytest -q`
  Под `-n` к имени добавляется работник (`..._b_gw0`), и такие базы заводятся
  сами — своё имя базы нужно всё равно, иначе две сессии сойдутся на `gw0`.
- **Рабочее дерево.** `git stash` из соседней сессии откатывает файлы под чужим
  прогоном. Не прятать чужие изменения; для долгой ветки — `git worktree`.
- **Номера решений вольта.** D-XXX уже дважды занимали одновременно. Брать номер
  в момент записи заголовка, а не заранее.

## Лицензионный заголовок

Проект под AGPL-3.0-only, и с прицелом на коммерческие лицензии. Поэтому каждый
исходник начинается с двух строк в стиле комментариев своего языка:

    SPDX-License-Identifier: AGPL-3.0-only
    Copyright (C) 2026 Nurlan Urazkulov

Новый файл заводится сразу с ними. Не первой строкой, если первой обязана идти
другая — шебанг, `<!doctype html>`, BOM: заголовок встаёт следом.

Что покрывается, а что нет — решает `tools/spdx.py`, а не догадка: списки там,
с объяснением каждого исключения (миграции Alembic, лок-файлы, ассеты, чужие
тексты лицензий, конфигурация). Спорный файл дописывается в списки, а не
обсуждается с проверкой.

Проверка идёт в CI и в `pre-commit`. Чинится одной командой из корня:

```bash
python tools/spdx.py --apply
```

Чужой копирайт не трогать и не переписывать — ни в заголовке, ни рядом. Файл с
чужим копирайтом скрипт обходит стороной и говорит об этом отдельной строкой.

## Планка качества

Это не пет-проект: большой продукт с долгим будущим, код должен оставаться
масштабируемым и поддерживаемым. Ревью 2026-08-23 дало 5/10 — документ с
оценками и программой в четырёх волнах: `../everselife-vault/90-production/09-code-review-2026-08-23.md`.
Перед любой задачей — свериться с ним; закрытые пункты вычёркивать там же.

Правила, которые нельзя нарушать молча:

- **Файл длиннее 800 строк** — перед правкой сказать об этом и предложить
  разрез. Добавлять в такой файл без упоминания нельзя. Список на 2026-08-31,
  от худшего: `api.ts` (1675), `panels/Admin.tsx` (1300),
  `engine/bank.py` (1298), `engine/market.py` (1245),
  `engine/travel.py` (1028), `engine/vote.py` (957), `engine/mining.py` (931),
  `engine/oxygen.py` (863), `engine/net.py` (863), `engine/frost.py` (828).
  Список **устаревает** — считать заново (`wc -l`), а не верить ему на слово:
  прошлый пересчитывали 2026-08-29, и за два дня два файла из него не
  уменьшились, а выросли.
  Разрезанное: `engine/explore.py` → пакет `engine/explore/` (`_base`, `odds`,
  `site`, `run`); `seed.py` → `seed.py` + `seed_parts.py` + `seed_catchup.py`;
  `engine/city/polity.py` (1084) → `founding`, `law`, `office`, `citizen` и
  `hall` в том же пакете, стек закреплён контрактами `import-linter`;
  `engine/world.py` (932) → пакет `engine/world/` (`land`, `people`, `things`).
- **Деньги, количества, остатки, выносливость** меняются только под
  блокировкой строки (`with_for_update`) или SQL-выражением
  (`col = col - :x`), и к каждой такой правке — тест-гонка на две сессии.
- **Чтение не пишет.** `look`, `*.view`, `*.status` не создают и не меняют
  строки. Что должно тикать — тикает в задании воркера.
- **Новый ключ в ответе сокета** — только если клиент не может вывести его
  из уже отданного (D-225). Константы каталога — в `/public/*`, не в `look`.
- **Таймер на клиенте** (`setInterval`/`setTimeout` для данных) — нарушение
  D-226, пока исключение не записано в `08-session-protocol.md`. Сервер
  говорит сам; клиент перечитывает по `touches`.
- **Ленивый импорт** (`from src.engine import x` внутри функции) — только с
  комментарием, какой цикл он разрывает. Иначе наверх. Слои:
  `api → engine → models → constants`, обратных рёбер нет.
- **Ответ на команду — подтверждение, не состояние.** Состояние приходит
  событием.
- **Миграция проверяется на чистой базе**, а не на dev-овской: заводится новая
  и прогоняется `alembic upgrade head` целиком. Dev-база уже мигрирована по
  шагам и не ловит поломку пути «с нуля» — так прошёл в main дефект с
  `ddl.RULES`: начальная миграция проигрывает весь набор правил на схеме, где
  таблицы ещё нет в нужном виде. Правило, верное только для новой схемы, в
  `RULES` не кладётся.
- **Схема из моделей и мигрированная схема — одна схема.** Тесты поднимают её
  `create_all`, прод — цепочкой миграций, и разойтись они могут молча: SQLAlchemy
  объявляет `Sequence`, но не принадлежность, поэтому `event_id_seq` в тестовой
  базе стоял сам по себе, а в мигрированной принадлежал `event.id` — и
  `TRUNCATE ... RESTART IDENTITY` вёл себя в них по-разному. Что не выражается
  моделью (принадлежность, триггеры, партиции), идёт в `db.ddl.RULES`, а не в
  одну лишь миграцию, и пришпиливается тестом сразу в обеих схемах
  (`tests/test_migrations.py`).
- **Один базовый класс отказа** (`engine/errors.Refusal`), когда он появится
  (волна 3); новые `XError` наследуют его.
- Перед завершением задачи крупнее одного файла — запустить агента
  `reviewer` (`.claude/agents/reviewer.md`) и ответить на его замечания.
